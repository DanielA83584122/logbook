# Design review — September 16, 2026

## Resolution — September 16, 2026

Subsequent user-directed changes replace the persistent selected tag tab with a sidebar that appears from the outer half of a slightly wider left margin. It contains a “logbook” home link and wrapping tag pills; the remaining page blurs and dims while it is open. Inline tags now share rounded, spaced pill styling in saved and editable text. Page controls are grouped with animated, background-free hover states. Sessions save with Enter in either field and have no submit button. Hidden outline help text is positioned within its outline to prevent invisible document overflow beyond the logbook.

All twelve findings below have been addressed. The original review is retained as historical evidence; its recommendations and blocking verdict describe the earlier implementation.

| Finding | Implemented resolution | Verification |
| --- | --- | --- |
| 1. Intermediate-width readability | Document width now contracts continuously; nested indentation shrinks at smaller widths. | Browser layout tests and responsive visual inspection |
| 2. Timer lost with long to-do lists | Timer stays fixed in its document column; to-dos expand without internal scrolling and can be folded. | Long-list browser test and 35-item visual probe |
| 3. Inconsistent short durations | Date, session, and statistics durations include seconds. Session duration edits accept `HH:MM:SS` and units such as `30s`. | Exact-duration browser tests, including preservation of start seconds |
| 4. Misleading zero bars | Zero days have zero-height bars; chart scale follows actual recorded focus. | Browser assertions of rendered bar heights |
| 5. Invisible active filter | Selected tag remains visible while other tabs stay hover-revealed, including medium layouts. | Tag and responsive browser tests |
| 6. Unclear averages | Statistics specify completed sessions and offer calendar-day or active-day averaging. | Statistics browser tests |
| 7. Document editing boundaries | Arrow navigation, boundary merges, list-wide selection and formatting, rich paste, and shared persistent undo/redo cross bullet boundaries. | Browser workflow tests and transactional history tests |
| 8. Task recovery | Parents show direct-child pie progress and complete automatically. Finished children remain dimmed until their immediate parent completes. Completion can be undone, preserving edited journal entries. | Browser completion/undo tests and backend hierarchy/history tests |
| 9. Tag movement | Committed chips settle at their trailing position during editing; shortcut whitespace is removed. Tags stay outside Markdown. | Tag persistence and mid-bullet shortcut browser tests |
| 10. Archive retrieval | Command/Ctrl+F searches all stored entries and opens matching dates and ancestors. | Browser test opening an unloaded nested entry from 2010 |
| 11. Sound and statistics access | Timer context menu exposes mute and volume in tiny mode. Statistics has an icon beside the theme toggle. Both have keyboard shortcuts. | Browser timer/sound/statistics tests |
| 12. Small click targets | Repeated document controls use 40 px desktop and 44 px touch targets. | Source inspection and browser accessibility checks |

The additional session-modal request is implemented: date and total heading, borderless start-time/duration rows, animated × delete controls, and a small + below the list. There are no visible field labels, statistics link, or close button. Click outside or Escape closes it. Add, edit, and delete update the day total.

Final automated validation: **49 backend tests and 42 browser tests passed**. The TypeScript/Vite production build passed. The personal SQLite database passed read-only integrity and foreign-key checks at schema version 6. Completion uses the existing `completed_at` field; progress and visibility are derived. Shared undo uses normalized `document_operations` and `document_changes` tables.

Final visual inspection used mocked API data in both themes, including parent progress, retained completed children, session viewing/editing, widths of 641/640/440/260 px, and a 35-item to-do list. No browser page errors occurred. Evidence: [measurements](/tmp/still-final-review/measurements.json), [document](/tmp/still-final-review/day.png), [sessions](/tmp/still-final-review/sessions-day.png), [night sessions](/tmp/still-final-review/sessions-night.png).

**Current verdict: Approve for the inspected scope.** Physical touch/pen behavior, screen-reader navigation, subjective audio quality, and performance with thousands of loaded bullets remain unverified. The original review below includes its motion inspection and other boundaries.

## Original review (superseded)

The main weakness is the mismatch between the page’s document appearance and its interaction model. The visual direction is consistent, but important state can disappear, ordinary document actions stop at bullet boundaries, and compact layouts can sacrifice readability.

This is a **full review** of the React/TypeScript interface, using the existing styled-components system and the make-interfaces-feel-better skill. Scope: the document, nested notes and tasks, tags, timer, themes, session editing, statistics, scrolling, and responsive layouts. The user’s request for a quiet document takes precedence over generic recommendations to add labels, toolbars, icons, or larger rows everywhere.

There are **12 remaining findings** and **2 changes completed at the user’s request during the review**. The findings below are recommendations, not changes already made. Browser probes used mocked data; the application’s personal database was not modified by the review. Backend correctness, security, and a comprehensive accessibility audit are outside this design review.

## Verification

- `npm run build`: passed after the two requested changes. Vite reports an approximately 893 kB uncompressed main chunk; this is a profiling candidate, not evidence of measured UI lag.
- `npx playwright test tests/logbook.spec.ts tests/tags.spec.ts`: **18 passed** on the final build. Includes hover preview, click persistence, click-to-close, keyboard expansion, editing inside collapsed branches, nested notes/tasks, completion, autosave recovery, midnight rollover, pagination, tags, and automated accessibility checks for the journal/statistics paths in that suite.
- `node /tmp/still-design-review/probe.mjs`: browser inspection with mocked data. Measured widths, nested text width, control hit areas, hidden filter state, short-session displays, zero chart bars, tag relocation, editor navigation, and timer position with 35 tasks. No browser page errors were reported. Raw evidence: [findings.json](/tmp/still-design-review/findings.json).
- Additional browser checks: empty to-do focus/blur, pending empty nested to-do, absence of database writes for empty drafts, night mode, and reduced-motion transition overrides. The final empty-draft implementation preserves the pending editor’s position instead of resetting it on blur, preventing a focus change from interrupting a click on another nested item.
- Completion motion was observed at normal speed and at 10% playback using the browser animation API. Because DOM removal is timed independently, this is not a timing benchmark. Entrance/exit shapes and displacement were inspected; no additional motion is proposed.
- Light/night and modal screenshots were inspected. Responsive probes covered 1280, 900, 700, 641, 640, 440, 301, and 260 px widths. The browser suite covered compact and timer-only layouts.
- **Not verified:** physical touch/pen behavior, screen-reader navigation, subjective audio quality, performance with thousands of loaded bullets, or every combination of modal/error/loading state. No claim of exhaustive usability testing is made.

**Original verdict (superseded): Block** on the then-remaining HIGH findings: unreadable intermediate/nested layouts, inconsistent exact durations, misleading zero-value bars, and invisible active filters. These findings are resolved in the implementation described at the top of this document. The unverified areas listed above remain outside the verdict’s evidence.
